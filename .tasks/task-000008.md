## Problema

Na aba **Social → Meu perfil → Lists**, a tela de listas públicas está com layout quebrado e conteúdo pouco útil para o usuário.

Ao acessar a aba, aparece erro visual de **Bottom overflowed** e a lista mostra IDs numéricos e enums técnicos como `PLAN_TO_WATCH`, `COMPLETED`, `DROPPED`, `WATCHING`, em vez de nomes de listas/status amigáveis.

## Evidência observada

Fluxo testado no browser:

1. Abrir a aplicação web.
2. Acessar **Social**.
3. Clicar em **Meu perfil**.
4. Abrir a aba **Lists**.

Comportamento observado:

- A tela exibe itens como:
  - `350 PLAN_TO_WATCH`
  - `155 COMPLETED`
  - `272 COMPLETED`
- A API retorna dados mais ricos, incluindo `title`, `posterUrl`, `status`, `rating` e `mediaType`.
- Exemplo de títulos retornados pela API:
  - `O Diabo Veste Prada`
  - `Batman: O Cavaleiro das Trevas`
  - `Batman Begins`
  - `Interestelar`
  - `Reacher`
- A UI não usa esses títulos na apresentação principal.
- O layout estoura verticalmente com mensagem **BOTTOM OVERFLOWED BY 226 PIXELS**.

## Comportamento atual

- A aba **Lists** mostra IDs de mídia e enums técnicos.
- O conteúdo parece uma lista crua de registros, não uma experiência social/public profile.
- O layout não respeita o espaço disponível e causa overflow próximo à barra inferior.

## Comportamento esperado

A aba **Lists** deve mostrar as listas públicas do usuário de forma amigável, por exemplo:

- **Quero ver**
- **Vendo / Assistindo**
- **Concluído**
- **Abandonado**

Dentro de cada lista, os itens devem usar informações legíveis da API, como:

- título da mídia;
- poster, quando disponível;
- tipo de mídia, se relevante;
- nota/rating, se houver;
- status traduzido/localizado, sem expor enums crus.

O layout deve ser rolável e não deve apresentar bottom overflow em telas menores.

## Critérios de aceite

- [ ] A aba **Social → Meu perfil → Lists** não apresenta erro de bottom overflow.
- [ ] A tela é rolável quando houver mais conteúdo do que espaço disponível.
- [ ] IDs numéricos de mídia deixam de ser o texto principal exibido ao usuário.
- [ ] Enums técnicos (`PLAN_TO_WATCH`, `COMPLETED`, `DROPPED`, `WATCHING`) não são exibidos crus.
- [ ] Os status/listas são exibidos com labels amigáveis/localizados, como **Quero ver**, **Assistindo**, **Concluído**, **Abandonado**.
- [ ] Os itens usam `title` retornado pela API quando disponível.
- [ ] A apresentação visual da aba Lists fica consistente com o restante da área Social/perfil.
- [ ] Testes cobrem o rendering da aba Lists com múltiplos itens e garantem ausência de overflow em layout típico.

## Observações técnicas

Investigar o widget responsável pela aba **Lists** no perfil social.

A chamada observada foi:

`GET /profiles/{profileId}/lists?limit=20`

Ela retorna dados suficientes para uma UI mais rica (`title`, `posterUrl`, `mediaType`, `status`, `rating`), mas a tela atual parece renderizar principalmente `mediaId` e `status`.
