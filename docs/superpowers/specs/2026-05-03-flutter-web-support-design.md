# Design: Flutter Web Platform Support

**Date:** 2026-05-03
**Status:** Approved
**Scope:** Enable SPA web platform in existing Flutter mobile app (lorebase-frontend)

---

## 1. Goals

- Add web as a fully supported Flutter platform alongside Android/iOS
- Same feature parity as mobile (SPA completa)
- Path-based URLs (`/dashboard`, `/login`) without hash
- Zero regressions on existing mobile platforms

## 2. Current State Assessment

| Aspect | Status |
|---|---|
| Platform-specific imports (`dart:io`, `dart:html`, `Platform.`, `kIsWeb`) | None found — clean codebase |
| State management (Riverpod) | Web-compatible |
| Navigation (GoRouter) | Web-compatible, needs `url_strategy` for path-based |
| HTTP (Dio) | Web-compatible |
| Auth (Amplify Auth Cognito 1.6.0) | Web-compatible, SRP-based sign-in works |
| Storage (`flutter_secure_storage`) | Falls back to IndexedDB on web (acceptable for MVP) |
| `flutter_dotenv` | Web-compatible |

## 3. Architecture

### 3.1 Platform Enablement

```bash
flutter create --platforms=web .
```

Creates `web/` directory with:
- `index.html` — entry point, loads Flutter engine via `flutter.js`
- `manifest.json` — PWA manifest
- `favicon.png` — app icon

### 3.2 Path-Based URL Strategy

GoRouter defaults to hash-based URLs on web. Switch to path-based:

```dart
// main.dart — before runApp
import 'package:url_strategy/url_strategy.dart';

void main() async {
  usePathUrlStrategy();
  WidgetsFlutterBinding.ensureInitialized();
  // ... existing init
}
```

**New dependency:** `url_strategy: ^0.3.0`

**Deployment note:** Hosting server must serve `index.html` for all routes (SPA fallback). Supported natively by Vercel, Netlify, Firebase Hosting, AWS S3+CloudFront.

### 3.3 Browser Tab Title

Set via `MaterialApp(title: 'Lorebase', ...)` in `app.dart` (already exists). Also update `<title>` in `web/index.html`.

### 3.4 Router — No Changes Required

`lib/router.dart` remains identical. GoRouter path-based mode is transparent to route definitions. Existing redirect logic works unchanged:
- Unauthenticated → redirect to `/login`
- Authenticated on auth routes → redirect to `/dashboard`

### 3.5 Auth & Secure Storage

**Amplify Auth Cognito:** Works on web without code changes. SRP protocol for email+password sign-in is platform-agnostic. `amplifyconfiguration.dart` requires no modifications.

**flutter_secure_storage:** Uses IndexedDB on web (vs Keychain/Keystore on mobile). Security is lower but acceptable for web MVPs. Future optimization: migrate to `amplify_secure_storage` for web crypto support.

## 4. Responsive Layout Strategy

### 4.1 Approach: Incremental, LayoutBuilder-based

No third-party responsive framework. Use Flutter's built-in `LayoutBuilder` with project-level breakpoints.

### 4.2 Breakpoints

```dart
// lib/core/responsive/breakpoints.dart
class Breakpoints {
  static const double mobile = 600;
  static const double tablet = 900;
}

enum ScreenSize { mobile, tablet, desktop }

ScreenSize getScreenSize(BuildContext context) {
  final width = MediaQuery.of(context).size.width;
  if (width >= Breakpoints.tablet) return ScreenSize.desktop;
  if (width >= Breakpoints.mobile) return ScreenSize.tablet;
  return ScreenSize.mobile;
}
```

### 4.3 Content Width Constraint

Wrap page content in `ConstrainedBox(maxWidth: 1200)` to prevent stretching on wide screens:

```dart
Center(
  child: ConstrainedBox(
    constraints: const BoxConstraints(maxWidth: 1200),
    child: child,
  ),
)
```

### 4.4 Navigation Shell Evolution (Phase 1 — MVP)

Current `ScaffoldWithNavBar` with `BottomNavigationBar` stays as-is. On desktop breakpoints, the BottomNavigationBar remains functional. Full `NavigationRail`/sidebar adaptation is deferred to Phase 2.

### 4.5 Phase 2 (Future)

- Desktop: `NavigationRail` on the left edge
- Tablet: Adaptive `BottomNavigationBar` or compact `NavigationRail`
- Sidebar with collapsible behavior

## 7. Rollout Plan

1. Enable web platform (`flutter create --platforms=web .`)
2. Add `url_strategy` dependency
3. Update `main.dart` with `usePathUrlStrategy()`
4. Add responsive breakpoints
5. Test full auth flow in Chrome
6. Manual QA on all routes at multiple viewport sizes
7. Deploy to hosting (Vercel/Firebase) for staging review

## 8. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Amplify Auth fails on web due to browser restrictions | High — blocks login | Test auth flow first; fallback: use `signInWithWebUI` (hosted UI) |
| `flutter_secure_storage` IndexedDB limitations | Medium — token storage | Monitor; migrate to `amplify_secure_storage` if needed |
| Large Flutter engine JS bundle (~1.5MB) | Medium — slow first load | Acceptable for SPA; future: deferred loading, code splitting |
| Scroll behavior differs on web | Low — UX friction | Use `ScrollConfiguration` with mouse/trackpad behavior |
